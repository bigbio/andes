# RS³ implementation report

**Branch:** `feat/rs3-scoring` (off `main` 780b8cd8)
**Date:** 2026-06-29
**Status:** DONE_WITH_CONCERNS (functionally complete + green; cost unmeasurable on the tiny repo fixture, and the gain is unvalidated — by design, validation is a separate entrapment-FDP benchmark gate)

## What was built

A per-spectrum **decoy-calibrated empirical null of the REAL emitted score**,
emitted as two additive trailing PIN columns behind `--rs3` (default OFF).
This is exactly the construction the 2026-06-29 CAMPAIGN RULING mandates: the
null is built by scoring N random decoy peptides with the SAME `score_psm`
path the engine uses for real candidates, so it calibrates the EXACT emitted
score with zero replication risk. It is **NOT** the superseded §2 analytic
CGF/saddlepoint, **NOT** a surrogate `g(m)`, and **NOT** any
score-enumeration generating function / DP (the patent-encumbered object).

## Recon findings (file:line)

- **Real per-candidate score** = `score_psm(scored_spec, peptide, scorer, charge, fragment_tolerance_da)`
  (`crates/scoring/src/scoring/psm_score.rs:234-368`). It only consumes the
  peptide's residue masses + length and the prepared spectrum, so a synthetic
  decoy `Peptide` is a drop-in.
- **Emitted PIN score** = `pin_score = score_psm(...) + cleavage_credit`
  (`crates/search/src/match_engine.rs:906`), where `compute_cleavage_credit`
  is a local `fn` at `match_engine.rs:791`.
- **Per-spectrum loop** is a `par_iter().enumerate()` closure over spectra
  (`match_engine.rs:531-535`); `spec_idx` (deterministic seed source), `scorer`,
  `fragment_tolerance_da`, `aa_set_for_scoring`, and `params: &SearchParams` are
  all in scope throughout.
- **Per-PSM feature fill** happens in the `queue.fill_post_topn(...)` closure at
  `match_engine.rs:1050-1100` (and a 2nd pass for `strong_score_cal` at ~1106),
  exactly where `delta_raw_score` / `tailor_score` / `rank_score_float` are set.
- **PsmFeatures struct**: `crates/search/src/psm.rs:12-234`.
- **PIN writer**: value list `psm_feature_values` (`crates/output/src/pin.rs:149-207`)
  + header list (`pin.rs:~448`), in lock-step. Rank-1 gating mirrors
  `DeltaRankScore` (`pin.rs:156`, `if rank == 1`). The PIN writer assigns rank 1
  to **all** PSMs tied at the max `rank_score`
  (`crates/output/src/row_context.rs:59-77`).
- **qpx mirror**: `crates/output/src/qpx.rs:500` reuses `psm_feature_values`, so
  the new columns flow through automatically. The separate `additional_scores`
  array (`qpx.rs:639`) is a curated subset, not a full PIN mirror — RS³ (not a
  headline score) was intentionally left out of it.

## Integration point chosen

The decoy null is computed **inside `run_chunk_inner`** for the rank-1 PSM,
**after** the optional Strong-mode reorder/trim
(`match_engine.rs`, immediately after the `if params.score_mode == ScoreMode::Strong { … }`
block), so "rank-1" reflects the final `rank_score` ordering the PIN writer uses.
It calls `scoring::rs3::rs3_features(...)` once, then assigns the two values to
every PSM tied at the top `rank_score` via a `fill_post_topn` pass (rank>1 rows
keep 0.0). This places RS³ where the real per-candidate scoring primitives and
the per-spectrum context are already in scope — no streaming/chunking obstacle.

Inputs threaded to the null:
- `observed_score` = the rank-1 PSM's `psm.score` (the emitted RawScore).
- `cleavage_credit` = `psm.score − score_psm(node sum)` — the winner's own
  credit, added to each decoy so the null sits on the same additive scale.
- `target_residue_mass` = `ScoredSpectrum::parent_mass() − H2O` (parent_mass is
  the precursor NEUTRAL mass; the decoy walk sums RESIDUE masses).
- `mass_tol_da` = max of the (possibly asymmetric) precursor tolerance left/right
  in Da at this mass, floored at 0.5 Da.
- `scan_seed` = `spec_idx`.

## Decoy / null implementation (`crates/scoring/src/scoring/rs3.rs`)

- `RS3_DECOY_COUNT = 256` (tunable const). The smallest non-degenerate p-value is
  `1/(N+1)` → `Rs3NegLog10P` caps near `log10(257) ≈ 2.41`.
- Deterministic `Lcg` (MMIX/Knuth constants) seeded from `scan_seed` mixed with
  the quantized target mass. No `rand` crate, no system time (both banned).
- Per decoy: grow a random AA walk (20 standard residues, cached masses) until
  its residue-mass sum lands within `mass_tol_da` of the target; abandon
  infeasible/too-short draws. One reusable residue buffer → the whole null is one
  allocation, not N. Each accepted decoy is scored via `score_psm` and shifted by
  the shared `cleavage_credit`.
- `Rs3NegLog10P = -log10((#{decoy_score >= observed}+1)/(n_scored+1))`
  (inclusive `>=`, Laplace-smoothed over the decoys actually scored → never `-inf`,
  conservative).
- `Rs3StdScore = (observed − mean(decoy))/stdev(decoy)`, guarded `var>0` else 0.0.
- Returns all-zero on degenerate inputs (non-positive target mass, no feasible
  decoy) — matching the off-path / rank>1 sentinel.
- 4 module unit tests (LCG determinism, distinct-seed divergence, index range,
  default sentinel).

## Flag wiring

- `--rs3` (bool, default false) added to `crates/andes/src/bin/andes.rs` next to
  `--refine`, assigned to `params.rs3` next to the `--chimeric` wiring.
- `SearchParams.rs3: bool` (`crates/search/src/search_params.rs`), defaulted false
  in `default_tryptic` and in the 3 exhaustive test literals
  (`mass_calibrator.rs`, `pin.rs`, `tsv.rs`); the calibrator prepass and the
  candidate-index/gen literals use `..params.clone()` spread (no change needed).
- OFF path: the entire decoy-null block is skipped (zero cost); the two columns
  still emit 0.0, so the PIN schema is identical with or without the flag.

## Rough per-spectrum cost

`N=256 × score_psm` per spectrum **that has a rank-1 PSM**, only under `--rs3`.
`score_psm` is O(peptide_length) cached node lookups (~10-40 splits), i.e. a tiny
fraction of the per-spectrum work (which scans thousands of candidates). On the
repo fixture (BSA = 1 protein, few candidates, dominated by model load + I/O) the
on/off wall times are within noise (~0.30 vs ~0.30 s) — **the fixture is too small
to measure the overhead**. On a real dataset where most spectra get a top PSM,
expect single-digit to low-double-digit percent added wall time; this should be
measured on the UPS1 low-res benchmark before any default-on consideration.

## Concerns

1. **Gain is unvalidated** (by design). Per the design doc's Gate 1, RS³ ships as
   additive features only if it yields a net PSM gain on UPS1 low-res at 1% true
   entrapment-FDP with no Astral/TMT regression. This implementation delivers the
   feature; the benchmark A/B is the next, separate step. Per
   [parity-tuning-lessons], a flat Percolator result here is an honest negative.
2. **Cost not measurable on the repo fixture** — see above; needs a real-dataset
   timing before default-on.
3. **Decoy realism**: decoys are uniform draws over the 20 standard residues with
   tryptic-style flanks, mass-constrained to the precursor window. They are NOT
   constrained to be tryptic or to match the target length distribution exactly
   (the greedy walk's length is mass-driven). This is a deliberately simple,
   parameter-light null; if Gate 0/1 shows the null is mis-scaled, the residue
   distribution (uniform vs natural-abundance) or a length match are the first
   knobs to revisit.
4. **Tie convention**: RS³ is assigned to all PSMs tied at the top `rank_score`
   (matching the PIN writer's rank-1 assignment), so on a tie the same value
   appears on >1 row — identical to how `DeltaRankScore` behaves.
5. **No FDR/Percolator changes** — RS³ is an andes feature only; Percolator
   remains the sole FDR tool. The decoy null here is a per-spectrum score
   calibration, unrelated to TDC.

# andes v2 — Own Per-Class Scoring Model (rank-based, three-level) — Design

**Date:** 2026-06-12 · **Status:** DESIGN — REVISED after adversarial validation (do NOT build as originally written) · **Visibility:** internal/local, NOT the public repo.

## 0. VALIDATION OUTCOME (2026-06-12, 6-skeptic adversarial pass)
**Verdict: SOUND-WITH-CHANGES — the architecture is wrong about *where* signals belong. Build at most an additive-feature L1/L2; kill L3 consensus-ID-copying. Test the riskiest claim FIRST.**
- **C3 consensus-search → REFUTED.** Copying one cluster ID onto every member spectrum and reporting it under cluster-level target/decoy is a statistically invalid error rate (member-level FDP runs several %). Keep clustering as an *accelerator only*; score each member individually with target+decoy, or report a *separate* transfer-error model — never under search FDR.
- **C5 non-redundancy → REFUTED.** 3 of 4 "new" L1 features (coverage, longest ladder, complementary b/y, matched-count) are **already shipped PIN columns** Percolator weights ~0 (LongestComplementaryLadder = +0.05). Only genuinely new axis = predicted-rank-vs-observed-rank agreement, and that sits on the rank paradigm already capped at −19% vs MS-GF+.
- **C1 RT-in-scoring → CONDITIONAL.** Load-bearing justification ("rescorers only see the top PSM") is FALSE — MSBooster/MS²Rescore/Percolator re-rank the top-N candidate list. In-scoring RT's unique gain likely flat once N≥5 vs writing top-N+RT to the PIN.
- **C2 two-pass calibration → CONDITIONAL (highest severity).** RT-consistency is structurally tilted toward targets (anchors are target-only; observed RT generated by the true peptide). Placed upstream of TDC it inflates FDP **invisibly** (depressed decoy count) — silent under the very 1%-FDR metric used to gate releases.
- **C4 pretrained GBT → CONDITIONAL.** A target/decoy-trained GBT upstream of TDC breaks decoy symmetry; PRIDE harvest/benchmark raw-file overlap risks memorization → phantom 1%-FDR gains. Must train target-vs-hard-negative (not vs decoys) + enforce corpus disjointness.
- **C6 speed → CONDITIONAL.** Baseline is wrong (andes is already ~16–40× *slower* than Sage, not faster); live clustering is hours-scale, only pays on redundant multi-run corpora. Make clustering OFF by default + ANN/LSH, never all-vs-all.

**REQUIRED CHANGES:** (1) drop consensus-search as an ID lever; (2) route RT + any new feature as **Percolator features over top-N PIN candidates**, NOT into the pre-TDC RawScore; (3) train the GBT target-vs-hard-negative + corpus-disjoint; (4) clustering off-by-default, redundancy-gated, ANN not all-vs-all; (5) state speed vs Sage/MSFragger.

**BUILD GATE — do E1 before ANY v2 code:** emit ONE additive PIN column (predicted-rank-vs-observed agreement), A/B against the **FULL current PIN** with **entrapment-FDP on Astral first**. PASS only if >1% PSMs at controlled FDP AND corr-with-RawScore < ~0.3 (the Sanov bar). If flat (the scar-history base rate: fragment-isotope/RL/CalibratedScore all flat) → **do not build v2; v1 own models ARE the release.** Full review: workflow wp8z26p21.

## 1. Goal
Replace andes's MS-GF+-derived intensity-rank scoring with an **own, per-class, rank-based scoring model**, trained on our own harvested corpora, that:
1. produces the **RawScore** used for identification (ranks candidate peptides within a spectrum, picks the ID),
2. is **fully independent of MS-GF+** (own architecture + own data → Apache-clean) and has **no external-predictor dependencies**,
3. is **fast** (objective #4),
4. **beats the engines on PSMs** at 1% FDR (objective #3).

Percolator stays the FDR/rescoring engine.

## 2. Non-goals
- Not reimplementing Prosit / ms2pip / DeepLC / AlphaPeptDeep. No external-predictor deps. (If a user runs them, their features layer in at *rescoring* — orthogonal to this design.)
- Not replacing Percolator.
- Not raw fragment-**intensity** prediction — we model **ranks**, which are instrument/method-robust and cheap to predict (the reason Prosit needs heavy DL is precisely to predict raw intensities; we sidestep that).

## 3. Organizing principle — three levels
A signal's **level** determines *where it is computed* (pretrained vs live) and *where it acts* (scoring vs rescoring vs preprocessing).

**Inside-the-RawScore test.** A signal belongs in the RawScore only if it (a) **discriminates candidates within one spectrum**, (b) is **not self-referential**, and (c) is **visible at the level where the score is computed** (a pretrained model can't see the user's dataset).

| Level | Signals | Computed | Acts in |
|---|---|---|---|
| **L1 — spectrum-intrinsic** | fragment-rank agreement; ion-series structure (b/y coverage, longest consecutive ladder, complementary b/y pairs, matched-ion count); cleavage propensity; mass-error consistency | **pretrained** per-class | **RawScore** (identification) |
| **L2 — per-run, candidate-discriminating** | RT-consistency (predicted vs observed) | **live, two-pass** per-run calibration | **RawScore** (identification) |
| **L3 — dataset-emergent** | cluster-size / cohesion; cross-spectrum peptide support | **live, on the user's dataset** | **consensus-search** (ID) + **Percolator** (FDR) |

Worked examples of the test: **RT** is L2 — each candidate has its own predicted RT (discriminates ✓), only per-run calibration is circular and the two-pass bounds it ✓ → inside the score. **Cluster-size** is L3 — identical for every candidate of a spectrum (fails (a)) and invisible to a pretrained model (fails (c)) → not a scoring feature. **Cross-spectrum support** is L3 — varies per candidate (passes (a)) but is self-referential (fails (b)) → rescoring only.

## 4. L1 — pretrained per-class RawScore model
**Role:** the core identification score (ranks all candidate peptides for a spectrum). Replaces the MS-GF+ intensity-rank LLR.

**Inputs (spectrum-intrinsic, rank-based, NOT raw intensity):** per-fragment intensity-**rank** agreement (predicted rank pattern vs observed), ion-series **coverage** (fraction of theoretical b/y matched), **longest consecutive ladder** (sequence-tag length), **complementary b/y pairs**, matched-ion count, **cleavage propensity** (learned per-residue cleavage likelihood — proline effect, enhanced C-terminal to D/E), mass-error consistency.

**Form — two tiers, so the inner loop stays cheap:**
- **Tier 1 (every candidate):** a fast **additive** rank+structure scorer with per-class learned weights (table-lookup speed). Ranks all candidates → keeps top-N.
- **Tier 2 (top-N only):** a per-class **gradient-boosted-tree** over the full rank+structure feature vector → refined RawScore. This is where the learning and the departure from MS-GF+ live; it is cheap because it runs only on the survivors.

**Training:** per protocol-class (activation × instrument × enzyme × protocol — TMT/phospho/iTRAQ/Automatic, the same taxonomy as the 39 slugs) on the harvested combined-FDR corpora. **Leakage-free by pretraining:** the model is trained on the harvest corpora and applied *blind* to the user's search; it never sees that search's target/decoy set, so its RawScore can feed Percolator with no double-dipping. Decoys in the live search are scored by the *same* model → symmetric → valid TDC.

**Why trees, not a DL net:** the layer is **tabular** (a feature vector per PSM) → gradient-boosted trees beat MLPs on tabular data, and inference is microsecond-cheap.

## 5. L2 — RT inside the score (two-pass), not a redundant Percolator feature
RT as a Percolator feature is **redundant** with DeepLC/ms2rescore downstream. The differentiated use is **inside** the RawScore: the candidate's **predicted-RT-vs-observed-RT consistency** is an input to the Tier-2 GBT, so RT influences *which peptide is identified* — recovering correct-but-ambiguous candidates at the identification step, which no downstream rescorer can do (they only see the final top PSM).

**Two-pass calibration (handles gradient-specificity + circularity):**
1. **Pass 1** — score with fragmentation only → high-confidence anchor IDs.
2. **Calibrate** the own RT predictor (simple: GBT or learned additive AA-retention coefficients) to *this run's* gradient from the anchors.
3. **Pass 2** — re-score top-N with RT-consistency now feeding the GBT.

RT is computed live per run; never shipped as a redundant Percolator column.

## 6. L3 — dataset-emergent (clustering, cross-spectrum)
These are **dataset-level / emergent** — a spectrum alone has no cluster-size; it exists only relative to the collection. Therefore they **cannot be pretrained** (the per-class model never sees the user's dataset) and must be computed **live at search-time.**

- **Consensus-search (identification lever):** own Rust spectral clustering → average cluster members into a higher-S/N **consensus spectrum** → search the consensus once → propagate the ID to members. Improves discrimination for *all* candidates + eliminates redundant searches (speed). Caveat: chimeric/mixed clusters can propagate a wrong ID → needs cohesion QC; ship the cluster-size feature first, treat consensus-search as an optional accelerator.
- **Cluster-size / cohesion (rescoring feature → Percolator):** a spectrum in a large, tight cluster is more likely a real peptide. Leakage-safe: cluster membership is a property of the *observed spectrum*, label-independent → target/decoy-symmetric, FDR-neutral.
- **Cross-spectrum peptide support (rescoring feature → Percolator):** varies per candidate but is **self-referential** (depends on other spectra's IDs) → kept in Percolator's TDC, which bounds the positive-feedback/error-amplification risk. Only folded into scoring later if a two-pass version passes entrapment.

## 7. Full pipeline
```
Pass 1:  andes FASTA search → Tier-1 additive rank score (every candidate) → top-N
         → high-confidence anchors → calibrate own RT model to this run
Pass 2:  Tier-2 per-class GBT( rank + ion-series + RT-consistency ) → RawScore (= identification)

Live dataset:  own spectral clustering → (optional) consensus-search;  cluster-size + cross-spectrum
RawScore  +  cluster-size/cohesion  +  cross-spectrum support   →   Percolator   →   FDR
            (RT NOT re-passed — DeepLC/ms2rescore owns the rescoring-RT axis if the user wants it)
```

## 8. Independence
Own architecture + own per-class training data + no MS-GF+ tables/structure + no external-predictor code/weights = the strongest possible Apache story; it makes the "seed-templated partition structure" concern moot for scoring.

## 9. Relationship to the v1 release
**v1** ships the *current* own intensity-rank per-class models now (already this paradigm: own data, per-class, used for identification) → unblocks the Apache + clean-start release immediately. **v2** is this model, replacing intensity-rank — same training pipeline + harvest, so nothing is wasted.

## 10. Load-bearing claims (must validate before building)
1. **RT-in-scoring recovers real IDs** — using RT inside the RawScore yields 1%-FDR IDs that "no-RT score + Percolator-with-RT-feature" does not (i.e., it isn't fully absorbed downstream).
2. **Two-pass RT calibration is not circular** and does not inflate FDP.
3. **Consensus-search preserves FDR** — clustering errors don't break target/decoy symmetry.
4. **Pretrained discriminative GBT RawScore → Percolator is leakage-free** (pretraining-on-different-data argument holds).
5. **Non-redundancy** — L1 rank + ion-series carries signal beyond andes's current PIN + Percolator (scar history: fragment-isotope, Residue-Lattice, CalibratedScore all came back flat by re-describing existing signal).
6. **Speed** — two-tier + live clustering + two-pass stays fast (objective #4).

## 11. Validation plan
Entrapment-FDP A/B per component on **Astral + UPS1 + a05058 TMT**; ablations; each load-bearing claim tested empirically *before* committing to build. Non-regression gate vs the current model on all three datasets.

## 12. Open risks
- GBT-per-candidate cost (mitigated by the Tier-1 additive prefilter).
- RT calibration robustness on short/irregular gradients (few anchors).
- Consensus-search chimeric-cluster ID propagation errors.
- Whether the per-class GBT beats the current LLR enough to justify the complexity (must pass the non-regression gate).

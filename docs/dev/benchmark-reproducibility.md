# Reproducible benchmarks

## Every benchmark result records

- andes commit (short hash) and date, the full command line, thread count.
- Hardware (CPU model, cores, RAM) and OS; whether it is the shared reference VM.
- Other tools' exact versions and parameter files.
- Rescoring method and seeds; database construction (decoys, entrapment).
- Wall, CPU time and peak RSS from `/usr/bin/time -v`.

## Rules

- Results live under `docs/benchmarks/results/`; tables in README and benchmark pages are
  generated by `docs/benchmarks/render.py`. Never hand-edit a generated block; regenerate
  and run `python3 -I docs/benchmarks/render.py --check`.
- Same settings for every engine where they exist (tolerances, enzyme, missed cleavages,
  modifications, rescoring); state every difference.
- Compare like with like: timings from different hosts are not comparable; mark them.
- Run the settings a user gets by default; tuned runs are labelled as such.
- Keep negative results: a tested idea that did not help is documented (as the DIA soft MS1
  gate was), so it is not re-tried blindly.
- Report ranges over runs and seeds, never a single best run.

## Reproduction

`docs/benchmarks/reproduce.md` must let someone else rerun a result from public inputs.
When adding a benchmark, add its reproduction steps in the same commit.

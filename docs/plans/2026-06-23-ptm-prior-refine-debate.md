# PTM-prior–weighted refinement — 5-agent debate synthesis (2026-06-23)

User idea: instead of andes's blind combinatorial refine cascade, attach to each protein the PTMs known at specific positions **with a probability** (UniProt / PhosphoSitePlus / PeptideAtlas / PRIDE-derived; optionally a small sequence→P(site) model), and **restrict/prioritize** the refine search toward high-prior common sites — to shrink the unknown space and surface extremely-common PTMs while keeping FDR honest.

Five parallel agents: prior-art, proponent, data-scout, adversarial-stats, adversarial-alternatives. They converged.

## Verdict: the *intuition* is right; the *mechanism as stated* (population priors restricting search) is dominated and FDR-dangerous. The winning forms are (1) sample-specific two-pass and (2) priors-as-a-rescoring-feature.

### Why "population priors restricting the search space" fails
1. **FATAL — decoy asymmetry (FDR landmine).** Reversed/shuffled decoys have, by construction, **zero annotated PTM sites** — the annotation DB cannot map to them. Any prior that boosts/permits target candidates at annotated sites is a term that fires on targets and **never on decoys** → target-decoy competition is structurally broken → q-values anti-conservative. Not tunable. Restriction is worst (changes the candidate space per target); a Bayesian score term is equally fatal; even a Percolator feature leaks ("is this a real protein" not "is this PSM correct").
2. **Circularity / reference bias.** Priors come from prior MS results → re-find the known, suppress the novel, self-fulfilling. PhosphoSitePlus single-evidence pS/pT/pY sets are ~82–98% FDR — the "high-prior tail" is partly noise you'd reify.
3. **Sample-specificity fallacy.** "Phosphorylated 99% of the time" is a cross-study marginal P(site modified | observed *ever*); the run needs P(modified | *this* sample/condition). Wrong conditional → precision degrades where stoichiometry is low (exactly where help is needed).
4. **Gain is in the wrong place.** Common PTMs are already found (high abundance, well-modeled); the value is rare/novel sites — which the prior actively suppresses. Restriction converts a discovery tool into a confirmation tool, and also shrinks the entrapment space asymmetrically so you can't even *measure* the recall you lost.

### The constructive convergence (all three of proponent + both adversaries agree)
- **Use priors as a SEPARATION lever, not a COVERAGE lever.** This resolves the tension with the project's "expand-then-discriminate" strategy: the prior's job is a decoy-symmetric, biology-derived discriminative signal Percolator currently lacks — NOT to search fewer mods. Used as a **PIN/rescorer feature** it's pure upside + FDR-safe (iff decoy-symmetric). Used as restriction it can only match-or-lose IDs; its only win is speed.
- **The *real* version of the idea is sample-specific two-pass (G-PTM-D), not population priors.** Pass-1 (wide/open) discovers which PTMs/sites are actually present in *this* sample; pass-2 restricts to those. FDR-defensible, +~20% mods with no FDR inflation in MetaMorpheus. andes already has the `--refine` Pass-2 cascade — this is the legitimate expression of the user's intuition, reusing existing infra. ⚠️ It inherits the project's known open problem: entrapment-FDP is structurally blind to peptide-anchored Pass-2 ([[refine-no-op-on-labeled-data-bug]]) → must ship with grouped/subset (Pass-2-own-decoy) FDR before banking any gain.

### Prior art (the gap is real)
Nobody has wired a **calibrated positional PTM probability into search-space construction while keeping FDR honest**. The two halves exist separately:
- Position-targeted search from **binary** annotation: PEFF + Comet (`\ModResPsi`, search only annotated positions); per-dataset-learned candidates: **MetaMorpheus G-PTM-D** (closest architectural precedent), **MSFragger mass-offset + PTM-Shepherd** (learns offset frequencies but does NOT auto-feed them back as priors — the documented missing automation).
- Probabilistic per-site PTM prediction: **DeepMVP** (Nat Methods 2025, trained on PTMAtlas = 397k sites from 241 reprocessed datasets; the ready-made "small model" the user described), MusiteDeep, DeepPhos — but used to **annotate / rescore / interpret**, never to drive search. Deep models that *do* lift phospho ID do it by **rescoring** (DeepRescore2 +17–46%), not search construction.

### Data reality (scout)
A real *calibrated* positional prior is buildable today only for a biased subset: **phospho-S/T, human/mouse, well-studied proteins.** Most sources give **presence, not frequency** (a real probability is impossible from them alone); detection-frequency (PeptideAtlas nObs, PhosphoSitePlus counts, CPTAC cross-sample) is broadly available but is *detectability* (abundance/enrichment-confounded), NOT biochemical occupancy; true occupancy exists for only ~5k phospho / ~6.8k acetyl sites (calibration set only). Ubiquitin-GG and methyl are presence-only with weak/no sequence prior. Severe Pareto/literature bias everywhere → mandatory log+smoothing.
- ★ **Licensing matters for the Apache-independence goal:** PhosphoSitePlus is **CC-BY-NC** (taints derived data, blocks commercial/permissive relicensing) — AVOID for a shippable prior. The clean stack is all CC-BY/open: **PeptideAtlas** Human Phosphoproteome build (free, positional, per-site nObs + PTMProphet confidence) + **Kinase Library** percentiles (Johnson 2023 / Yaffe 2024, from the CC-BY *paper* supplements not the NC code) as the sequence fallback + **UniProt MOD_RES** (CC-BY) as the positional mask. **DeepMVP** (PTMAtlas-trained) is the ready-made per-residue model. Calibration against the sparse occupancy sets is mandatory (none ship a calibrated probability).

## Recommendation for andes (ranked)
1. **Sample-specific two-pass (G-PTM-D-style) over the existing refine cascade** — pass-1 learns this sample's PTMs, pass-2 restricts to them. The honest, FDR-defensible version. Gated on **grouped/subset FDR** (the actual open problem, orthogonal to priors).
2. **Population/predicted priors as a Percolator/native-rescorer FEATURE, never a search restriction.** Cheapest, reversible, FDR-neutral. Concrete MVP: phospho-only, PhosphoSitePlus/PeptideAtlas priors → two additive PIN columns (`SitePriorLocalized`, `SitePriorMax`) in `mod_site_features.rs` + `pin.rs` (the proven additive-PIN-feature lever), on **PXD065579** (the phospho-enriched Astral set already harvested), gated at 1% true entrapment-FDP, **stratified annotated-vs-unannotated** (if the gain concentrates as annotated-site FDP inflation → that's the leak). DeepMVP could supply the prior for unannotated proteins.
3. **Do NOT build population-prior search-space restriction.** Dominated on discovery, FDR, and relevance; wins only raw speed in a niche (low-input / clinical known-panel) better served by a predicted spectral library or targeted assay.

### Two risks even the proponent can't design away (the empirical bet)
1. The **strong** part of the prior (annotation/occupancy) is structurally target-only/reference-biased; the **safe** part (sequence-motif model, decoy-symmetric) is weak — close to what andes geometry already captures. There may be no large decoy-symmetric biologically-informative prior.
2. The prior may be **redundant** with what Percolator already extracts from site-determining ions → could land **flat**, exactly like RichIonLLR did on a fixed search space ([[search-space-expansion-strategy]]). Mitigation (pair with mod-class expansion) is also what makes FDR hardest.

Only an MVP answers these. Recommended first experiment = #2 (prior-as-feature, phospho, PXD065579, entrapment-FDP, stratified).

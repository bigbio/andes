# StrucGP — N-glycopeptide structural search engine (tool study for andes)

Repo: [github.com/Sun-GlycoLab/StrucGP](https://github.com/Sun-GlycoLab/StrucGP) (Tcl/C); [Zenodo 7405508](https://zenodo.org/records/7405508). Data: PXD025859.

## 1. Candidate generation — **peptide-first, dual-energy paired spectra**
StrucGP does **not** do open/mass-offset or fragment-index search. It requires each precursor be fragmented at **two HCD energies** (or SCE): **low (~20%)** yields glycan **B/Y** ions; **high (~33%, 37% for TMT)** yields peptide **b/y** ions. The two scans form a **spectra pair**. Flow: (a) **oxonium gate** on the high-energy scan — top-20 peaks must contain ≥2 of {138.055, 204.087} (`Oxo_ess_n=2`); (b) match **Y1 candidates** in the low-energy scan ("Spectra pair with core-five glycans" = pairs matching ≥1 Y1) — this seeds the peptide-backbone (Y0/Y1) mass; (c) peptide sequence identified from the high-energy b/y ions against a tryptic protein DB (top-`n`≈300 peaks, `Min_pepfrag_number` gate); (d) glycan structure built de novo from low-energy B/Y. This is **peptide-DB-first with a Y1 anchor**, not glycan-Y-first.

## 2. Glycan handling — **database-INDEPENDENT modularization**
The signature idea. An N-glycan is decomposed into three modules, each read from characteristic B/Y ions: **(1) core** (the pentasaccharide + core-fucose), **(2) glycan type** (high-mannose / hybrid / complex / paucimannose), **(3) branch structures**. Only branches come from a small curated DB — `branch_structures.xlsx`, **17 verified branch types** (human+mouse), each entry carries *essential ions* (must appear), *forbidden ions* (must not appear), and composition. Because full glycans are **assembled combinatorially from modules**, not enumerated, StrucGP identifies **novel glycans absent from any composition DB** — its main differentiator vs a glyco search engine/a commercial glyco engine composition search. Oxonium ions are used only as a spectrum gate, not for scoring.

## 3. Scoring — **rule/ion-coverage based, NO learned or spectral-predictor model**
No published closed-form combined score. Peptide axis: b/y match against DB (classic PSM score). Glycan axis: each candidate structure gets a **probability per sub-structure** derived from presence/intensity of the diagnostic B/Y ions that define each module, plus spectral **"purity"** (fewer unmatched peaks = higher quality). Branch entries are hard-filtered by essential/forbidden ion rules before scoring. There is **no machine-learned fragment-intensity model and no cross-spectrum transfer** — this is exactly the axis andes should out-engineer.

## 4. FDR — **separate 2-axis (peptide & glycan), target-decoy**
- **Peptide axis:** reversed/decoy peptides generated from the protein DB at **1:1** target:decoy; standard peptide FDR. Warns DB must be >100 proteins or peptide FDR is unreliable.
- **Glycan axis:** **decoy spectra by adding a random mass (or masses) to the precursor** — a glycan-mass shift that breaks the true Y-ladder/composition match; glycan FDR from target vs these mass-shifted decoys. Accuracy scales with #identified spectra (DB-independent → empirical null), so they recommend an **absolute glycan-score floor (~50)** on top of FDR.
- Reported as **two independent thresholds**: `PSMs under peptide FDR 0.01` then `peptide & glycan FDR = 0.01` (sequential intersection, not a joint q-value surface). No entrapment.

## 5. Glycan notation — **layered structure code**
Emits an explicit topology string, not just composition. Uppercase = open a layer, lowercase = close; `A`=layer-1 from reducing end, `B`=layer-2, …; digits `1–5` = Hex, HexNAc, NeuAc, NeuGc, dHex. Example `A2B2C1D1E2edD2dD1dcB5ba` = composition N4H3F1. Composition abbrevs H/N/S/G/F.

## 7. Single most valuable clean-room idea + what to avoid
**BORROW: the glycan-axis decoy = random-mass-shifted precursor, scored on a SEPARATE FDR axis.** This is precisely the fix andes's `SPA2_RESULT` and G3 needs. andes's failure was feeding glycan decoys into **one** Percolator pile (recovery 29.4%→4.4%); StrucGP validates the **separate-axis** design. Clean-room recipe for andes: build a glyco-decoy by perturbing the *glycan* mass (random offset that invalidates the Y-ladder) while keeping the peptide, score its Y-ladder/oxonium features, and compute a **glycan q-value as a thin Percolator post-process on that axis only** — then intersect with the peptide-axis q≤0.01. This respects the hard constraint (Percolator-only, 2D-FDR = post-process). Also worth borrowing: the **modular branch DB with essential/forbidden-ion hard filters** as a cheap structural prior.

**AVOID:** (a) StrucGP's **peptide-first + mandatory dual-energy** requirement — andes is glycan-Y-first and targets single stepped-HCD; do not adopt paired-scan dependence. (b) Its **rule-based glycan probability** — andes's edge is *learned* peptide-axis scoring (SP-B) + in-process cross-spectrum transfer, which StrucGP lacks; do not regress to hand-tuned ion rules. (c) **Sequential-intersection FDR** as the only view — keep it, but andes should still route both axes through Percolator, not ad-hoc thresholds. (d) Any code reuse (license).
